# 局限与证据等级

## 一句话

BioForge Studio 是**假设生成与排序工具**，不是测量仪器、法规数据库或生产级分子模拟平台。

## 数据与模型

1. **稳定性先验不是实测值。** `Tm`、`pH50`、`dtm10_c`、`K_pct`、光稳定性、成熟时间等均为文献趋势校准的策展先验，用于相对排序。不同缓冲液、纯度、蛋白构象、光照和氧条件下会显著偏离。
2. **蛋白候选是策展集合，不是生成模型。** 序列与参数来自公开资源/文献近似值；没有做 de novo 序列生成、结构预测、折叠自由能计算或表达量预测。
3. **食品安全状态是简化标记。** 食品级/研究级标签不构成法规结论；天然色素的批准状态、纯度、溶剂残留、最大使用量和标签要求因地区/产品而异。荧光蛋白不是食品配料。
4. **光谱参考峰是近似值。** 溶剂、pH、仪器、浓度和基质会改变峰位与强度；不能替代标准品、校准和合规检测。
5. **数字孪生是唯象模型。** 使用一阶热/酸失活动力学、折叠分数和经验保护项；没有考虑聚集路径、界面失活、金属催化、酶解、微生物生长等。
6. **Monte Carlo 只覆盖设定扰动。** 温度 ±1°C、pH ±0.08、剂量 ±15%、Tm/pH50 正态扰动；不是完整的工艺能力分析。
7. **小分子荧光参数是近似。** 量子产率、光漂白、溶剂化变色和聚集猝灭未完整建模。
8. **训练样本要求高。** 少于 5 条拒绝训练，少于 30 条仅探索性；校正模型可能过拟合，必须外部验证。合成数据默认排除。
9. **快速 MM/QM 不是生产验证。** RDKit MMFF94s 只是几何/能量 sanity check；PySCF 默认未安装且接口仅做小分子快速检查；MD/QM 输出是实验计划，不是已完成的模拟。
10. **没有多用户、RBAC、审计。** 单 token 本地工具，不适合直接作为公网多租户服务。

## 解释输出时

- 优先看 `meets_spec`、总保留率、Δλem、谱形余弦、Monte Carlo 达标率和警告，而不是单一综合评分。
- 评分权重可被需求解析改变；它表达约束满足度，不是成功概率。
- 食品模式会过滤候选；`alternative_candidates` 中的研究级候选不能用于食品。
- 任何“基本不变”结论都必须用真实样品、目标基质、目标工艺和加速/货架实验证明。
- 报告中的法规文字是提醒，不是法律意见。

## 必须做的验证

1. 目标基质中的真实样品，至少 3 批次 × 3 技术重复。
2. 工艺温度/时间、pH、溶解氧、光照、顶空氧的实测与记录。
3. 荧光光谱（Ex/Em、强度、峰位、谱形）与 UV-Vis；必要时 IR/MS/NMR 确认身份。
4. 加速稳定性 + 实时货架期；微生物、感官、色差、包装相容性。
5. 食品/法规团队复核配料、最大使用量、标签、过敏原和销售地要求。
6. 蛋白/小分子的结构、纯度、活性、聚集和免疫原性（如适用）。
7. 统计预注册、等效边界、置信区间和异常值处理。

## 环境限制

- 当前机器磁盘约 15 GB 可用；Android SDK 已占约 458 MB，未安装模拟器。
- PySCF/OpenMM 为可选依赖；未安装时相关接口明确返回 unavailable。
- 离线 Web 在 `file://` 下可能无法使用 Service Worker；APK 不依赖 Service Worker。
- FPbase 在构建环境返回 403，未使用其数据；蛋白参数来自 UniProt/文献策展。

## v2.0.0 新增限制

1. **食品配方是模板/先验，不是可生产配方。** 配料百分比、pH、aw、货架期和工艺窗口由规则与经验模型生成；必须中试、微生物挑战、感官和法规核验。
2. **食品体系覆盖是策展集合。** 20 个体系覆盖常见类别，不代表所有地区/产品/工艺；特殊食品需扩展数据与规则。
3. **相互作用是方向性先验。** 46 条相互作用来自文献/教材的简化方向与强度，不是实测网络；负向作用会进入警告，但不等于真实配方一定失败。
4. **在线数据库有延迟/缺项/同名风险。** 交叉链接是候选匹配；PubChem 质谱记录不保证与配方条件一致；KEGG 默认不查询，MassBank 仅链接。
5. **登录是单账户本地鉴权。** 没有多用户/RBAC/审计；不要直接暴露公网。Token 只是本地 API 凭据。
6. **Vina 不是自由能。** 刚性受体、打分函数、质子化/构象采样有限；不能直接预测 Kd。
7. **GROMACS 2 ps 只做 sanity check。** 未做平衡、重复、长时程、自由能或 QM/MM；不能据此判断结合模式或稳定性。
8. **CP2K 单点是配体气相/周期盒。** 不含蛋白口袋、溶剂、熵和温度采样；不能单独证明机制。
9. **APK 需要服务器。** v2 APK 是 WebView 客户端；离线食品组合和在线证据不可用，v1 离线引擎仍保留。
10. **报告不是法规文件。** 标签、过敏原、最大使用量、健康声称必须由法规团队确认。

## v2.1.0 新增/修正限制

1. **实体分类仍可能误判。** 默认用关键词和显式 `entity`；简称、商品名、混合查询可能被分到错误实体。界面允许手动选择 `compound/protein/food/complex`。
2. **UniChem 映射不是完整覆盖。** 没有 UniChem 映射时，ChEBI/ChEMBL 会退化为名称搜索，并标记 `name_search`；这不是结构验证。
3. **FDC 实时 API 可能不可用。** `DEMO_KEY` 会 429；回退的 `local_fdc_snapshot` 是 2018 SR Legacy 快照，不是当前产品/批次，状态会显示 `degraded`。
4. **FDC 覆盖 35/96 个配料。** 剩余 61 个是 curated estimate；`mapped_mass_pct` 只说明配方质量覆盖，不说明数据完美。
5. **组成区间是假设。** ±8%/±15% 是工程筛选区间，不是统计置信区间或实验误差。
6. **确定性选择不等于最优。** 评分权重和 curated 规则会决定排序；换权重可能换配方。没有随机数只保证可复现，不保证唯一正确。
7. **pH/aw/稳定性/货架期仍是规则估算。** 见 `SCIENTIFIC_METHOD.md`；未做 pH 计、aw 仪、微生物挑战、加速/实时货架试验。
8. **感官/成本是代理指标。** 感官分不是人类品尝结果；成本指数不含采购、损耗、税费和中试。
9. **在线检索有速率/服务波动。** 单源错误不会中断整体，但可能缺失证据；缓存 24 小时可能保留旧记录。
10. **MassBank 仍是 link-only。** 不能把“未返回 JSON”包装成检索成功；谱图只作为 PubChem 记录的参考链接。
11. **实验证据仍为空（A 级）。** 本版本解决的是“数据来源和推理可追溯”，不是“配方已被实验证明”。
12. **APK 仍需服务器。** v2.1 APK 是 WebView 客户端；离线只能看壳/提示，v1 离线引擎保留。

## v3.2.0 新增限制

1. **3D 查看器是可视化投影，不是结构质量评估。** 卡通/线/球棍/空间填充按原子坐标绘制，不做能量最小化、电子密度拟合、二级结构指派或结合模式验证。
2. **图谱布局是启发式径向/力导向。** 节点距离、颜色和中心性不代表因果强度或证据质量；文献/数据源节点只表示“可追溯来源”。
3. **文献标签不是人工标注。** MeSH、作者关键词、化合物列表和 topic 都可能漏标/误标；BM25 不是向量检索或系统综述。
4. **本地全文覆盖极低。** 10,000 篇中仅 12 篇全文；其余只有摘要/元数据。Europe PMC PDF 端点仍可能 403。
5. **远程部署默认仍是单用户/受控团队。** 没有多租户隔离、企业 SSO、审计合规或按客户配额；公网暴露前需改密码、HTTPS 和访问控制。
6. **Docker 镜像不含 GROMACS/CP2K/Vina/HADDOCK。** 容器部署的 Web 功能可用，但机制计算仍需宿主工具或专用计算镜像。

## v3.1.0 新增限制

1. **LAN 明文 HTTP 是便利性取舍。** 服务绑定 `0.0.0.0:8010`、APK 启用明文 HTTP，只适合可信局域网；公网必须使用 HTTPS 反向代理和访问控制。
2. **HADDOCK3 是独立管线。** 仅支持蛋白-蛋白、蛋白-配体、蛋白-多糖三类工作流；依赖 HADDOCK3/RDKit 和本地结构缓存，参数错误、活性残基不当或糖链模板缺失会导致失败。HADDOCK score 是任意单位，不是结合自由能。
3. **3D 查看器是坐标可视化。** 只加载 RCSB PDB，不做结构预测、能量评估或结合模式验证；部分 PDB 可能下载失败。
4. **文献库不是系统综述。** 标签来自关键词规则，检索是 BM25；没有 PRISMA、人工筛查、偏倚评估或向量语义检索。
5. **全文覆盖很低。** 当前 10,000 篇元数据只有 12 篇全文 Markdown；Europe PMC PDF 端点返回 403/Cloudflare，全文主要来自 JATS XML。
6. **磁盘不足。** `/media/h3c/Win11Pro X64` 仅约 1.2 GB 可用，不能批量下载上万 PDF；文献库约 157 MB。
7. **未做真机验收。** 本机无 Android 设备/AVD；APK 首启配置、LAN WebView 登录和设置重开只在代码/构建层验证。
8. **计算仍不是生产级。** 刚性受体对接、短 MD、配体单点 QM 只能做排序/假设生成；参数可调不等于结果已被实验校准。
9. **运行指纹不是结果证书。** 指纹只证明目标+参数相同，不证明数值可逐位复现，也不证明科学正确。

## 2026-10-22 新增限制

- `query_text` 的相关度是词面/短语覆盖评分，不是语义向量相似度，也不是统计显著性。
- GenBank、KEGG 端点存在限流、条款变化或不可达的可能；失败只应降级为单源错误，不影响其他来源。ZINC 对自动 JSON 请求启用验证码，当前只提供 link-only 入口，不复制数据。
- DrugBank、CCDC、ChemBook、高校图书馆等来源需要许可或机构凭据；未授权前系统只登记状态和入口，不抓取、不复制数据。
- NMRShiftDB2、LIPID MAPS、GlyTouCan 当前是公开参考入口，不是完整的本地谱图/脂质/聚糖数据库。
- 加工预测是机理规则 + 文献先验的方向性模型；温度-时间曲线、传热、pH、离子强度、氧和基质会改变结果，必须中试和货架期验证。
- 3D 组分组是基于残基名/元素的启发式分类；非标准残基、修饰氨基酸和自定义配体可能分类错误，必须人工核对。
- 图谱节点/边的置信度表示来源等级（workflow/curated/online/verified/reference/model），不是统计置信区间或效应量。
- 案例数值随数据与算法调整；通过硬约束只代表满足该体系的筛选约束，不等于法规、安全或感官验收。


## 3.2.1 新增限制

- PostgreSQL 已同步语料，但 `embedding` 列尚未生成向量；当前只有全文检索，没有向量召回或 RAG 重排。
- SCUT/EZproxy 的具体入口取决于学校当前配置；软件只提供官方页面/可配置前缀，不自动登录、不抓取图书馆全部资源。
- 资源目录只列合法入口；Sci-Hub、付费墙绕过和验证码规避不提供。
- 第三方 API 受网络、限流和条款影响；Crossref/Unpaywall 可能超时，解析结果中的链接仍可用。
- 8003 是 RustDesk 远程服务端口，BioForge 固定改用 8010；部署时不要改回 8003。


## 3.2.2 新增限制

- 多组合对接最多 12 对；组合爆炸时不自动分批或排队，需用户缩小范围。
- `complex.pdb` 只是刚性受体与第一个 pose 的坐标拼装；复合物 MD 从该 pose 出发，但仍是短 NVT，不证明结合模式或结合自由能。
- 复合物 MD 使用自动配体质子化/电荷（ACPYPE GAFF2/AM1-BCC）和自动蛋白质子化；互变异构、质子化态、金属/辅因子和膜环境需人工复核。
- 复合物 MD 在“全部”模式按选定 pair 运行，耗时随组合数增加；CP2K 仍按唯一配体独立运行。
- EM 不保证收敛；实测 1BEB+quercetin 首轮 5000 步 Fmax 仍为 5707.8 kJ/mol/nm，自动二次 EM 244 步收敛到 456.8。必须查看 `em.log`/`result.gromacs.em_converged`，不能把未收敛 EM 当成平衡体系。
- 1GFL 等含非标准残基的结构会跳过无法模板匹配的残基；这可能删除关键环区或发色团，需人工检查准备后的受体。
- Ollama 问答依赖本机模型与内存，可能超时、答非所问或产生错误结论；历史文件含问题与回答，需按数据政策管理。
- Obsidian 只读浏览依赖本机挂载目录；目录不可用、文件被占用或编码异常时只显示错误，不影响其他功能。
- 双语覆盖导航、按钮、表单占位符、资源库/设置动态 UI 和指南；动态生成的案例、证据、笔记和图谱文本仍为原语言。
- `.xtc` 轨迹转换需要 `md.tpr` 和 GROMACS；首次转换可能耗时，长轨迹会生成较大 PDB，浏览器内存和加载时间需实测。
- 移动端 8 标签在 320–430 px 已用 8 列网格适配；更窄屏幕可能进一步缩小字号，但仍不保证所有语言标签完整可读。
- Ollama 仍可能空回答；已有重试与状态提示，但根因未完全定位，助手输出不能作为事实来源。
- 12 套主题纹理是 CSS 背景，不改变图表/3D 的科学含义；打印或低性能设备上可能简化。


## 3.3.0 RAG 额外限制

- 本地库无命中不代表没有研究；外部 OA 也可能限流、缺摘要或只有元数据。
- 质量分是规则评分，不是统计置信度；`strong` 仍不能替代人工阅读原文。
- 逐句核验只检查 `[E#]` 和词项重叠，不能发现所有无依据表述、因果倒置或统计错误。
- 人工审核由本地操作者完成，不是独立同行评审；`approved` 不代表法规/临床批准。
- 反馈更新的是关系排序权重，不是训练神经网络策略；样本不足时不能声称“RL 已进化”。
- DeepAgent 未在主进程启用；可选 worker 需要 Python ≥3.11 和额外依赖，未配置时不会运行。
- iOS/Android 的远程访问仍受网络、TLS、身份策略和登录会话影响；不要直接暴露明文 8010。

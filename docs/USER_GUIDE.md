# BioForge Studio 3.2.2 使用说明

本手册同时内置在应用“使用指南”页面，并同步到 Obsidian 文献库的 `00-BioForge/` 目录。

## 1. 启动与连接

### 本机

```bash
cd /home/h3c/md-agent/bioforge/v3.0.0
BIOFORGE_HOST=0.0.0.0 BIOFORGE_PORT=8010 ./scripts/run_server.sh
```

浏览器打开 `http://127.0.0.1:8010`。默认账号在 `runtime/login.txt`；首次登录后立即在“设置”修改密码。

### 手机局域网

手机和电脑连接同一 Wi-Fi，使用电脑的局域网 IP，例如 `http://10.194.51.41:8010`。`127.0.0.1` 只指手机自己，不能用来访问电脑。若打不开，检查防火墙、端口 8010 和 IP 是否变化。

### 远程客户

不要直接端口转发明文 HTTP。按 `docs/DEPLOYMENT.md` 使用 Cloudflare Tunnel、Tailscale 或 VPS + Caddy HTTPS。手机 APK 中填写 `https://` 地址。

## 2. 设计工作台

- **自动**：根据自然语言判断食品/生物设计。
- **食品配方**：输出配料占比、角色、相互作用、工艺、约束审计和风险。
- **生物设计**：输出蛋白/小分子候选、保护剂组合、Tm、工艺/货架保留率、亮度、光谱和验证计划。

结果阅读顺序：

1. 先看候选和综合评分；评分是加权决策指数，不是成功概率。
2. 再看硬约束和 `at_risk`；区间跨边界时必须实测。
3. 查看“为什么是这个组合”和“风险与待验证”。
4. 用“证据图谱”检查推理链。
5. 用“运行机制计算”生成对接/MD/QM 作业；计算结果仍需实验验证。

## 3. 证据图谱

- 滚轮/双指缩放，拖拽平移；点击节点查看详情。
- “按类型”区分设计、候选、保护剂、推理步骤、文献和数据源。
- “按连接度”突出枢纽节点；“按计算状态”区分已完成/计划中。
- 可隐藏数据源和推理链，便于聚焦核心配方。
- 数据源节点可打开原始数据库；文献节点是策展/元数据证据，不是临床结论。

## 4. 机制计算与 3D 查看器

- Vina：对接姿态与打分，不是结合自由能的实验测量。
- GROMACS：短 MD 检查局部稳定性；`md.gro` 是末帧结构，`md.xtc` 是轨迹文件。
- CP2K：小体系电子结构；不等于蛋白-配体自由能。
- 从作业卡片点击 `3D · receptor.pdb`、`3D · poses.pdbqt`、`3D · md.gro` 可在查看器中打开。
- 支持 PDB、PDBQT 多构象、GRO；可切换卡通/主链/球棍/空间填充，按元素/链/深度着色。
- 点击原子查看残基；下方单字母序列可点击定位；可导出当前视图 PNG。
- 作业卡片可导出参数/结果 JSON 与摘要 CSV。

## 5. 模型实验室

1. 导入 CSV/JSON，标记来源类型（实测、文献、模拟、合成、混合）。
2. 选择数据集、目标列、算法和交叉验证折数；合成数据必须显式确认。
3. 训练后查看 R²、MAE、残差、特征重要性和不确定性。
4. 用贝叶斯优化在训练范围内生成候选；不要把它当成外推预测。
5. 用真实实验结果回灌并重训；保留数据哈希和模型版本。

## 6. 本地文献库与标签

数据目录：`/media/h3c/Win11Pro X64/data/literature/`

- SQLite：`bioforge_literature.db`
- Obsidian：`obsidian/<year>/*.md`
- 全文：`fulltext/<paper_id>.md`
- XML：`xml/<paper_id>.xml`

在“在线证据”页底部搜索本地 OA 文献。标签映射：

| 标签 | 来源 |
|---|---|
| `topic/docking` 等 | 标题/摘要规则 |
| `mesh/...` | Europe PMC MeSH 主题词 |
| `keyword/...` | 作者关键词 |
| `chemical/...` | 化合物列表 |

当前库约 10,000 篇 OA 元数据、25,000+ 文本块、48,000+ 实体；全文 12 篇。BM25 检索不是系统综述，引用前必须核对原文和许可。

## 7. 数据、备份与恢复

需要备份：

- `runtime/`（账号、会话密钥、设计、作业、Lab 模型）
- `data/`（策展数据）
- 文献目录（数据库 + Obsidian + 全文）
- `logs/`（排障）

不要备份或提交到公开仓库：`runtime/.token`、`runtime/auth.json`、`runtime/.session_secret`、`.env`、私钥。

## 8. 故障排查

| 现象 | 处理 |
|---|---|
| 手机打不开 | 确认使用电脑局域网 IP + 8010；`127.0.0.1` 错误；检查同一 Wi-Fi 和防火墙 |
| 登录失败 | 查看 `runtime/login.txt`；密码已修改则使用新密码 |
| Internal Server Error | 查看 `logs/bioforge.log` / `/tmp/opencode/server-v32.log` |
| 公网 502 | 检查 Caddy/Tunnel 到 `app:8010` 的连通性；`docker compose logs` |
| 计算失败 | 展开“本地软件接口”检查 Vina/GROMACS/CP2K；查看作业 `error` |
| 3D 空白 | 确认结构文件有 ATOM/HETATM 或 GRO 原子行；检查浏览器控制台 |
| 文献检索 0 条 | 用更短关键词；确认 `BIOFORGE_LITERATURE_DB` 路径与权限 |

## 9. 结论边界

- 配方、模型、对接、MD、QM 与文献检索都是研究与设计决策支持。
- 不构成食品/药品/医疗器械的合规、安全性、有效性或临床结论。
- 合成/模拟数据不能替代湿实验。
- 文献标签可能漏标/误标，不能替代人工阅读。
- 公网部署前必须改密码、启用 HTTPS、限制访问并做好备份。

## 10. 3.2 更新：图谱、3D 组分、双语检索与加工预测

### 证据图谱（力导向 + 证据链）

- 图谱使用生长动画和力导向布局；可拖动节点（会牵拉相关节点）、拖背景平移、滚轮或双指缩放。
- 点击节点聚焦相关节点和边；双击节点打开证据面板；点击边查看关系含义、来源和证据。
- 面板中的 URL 只有主动点击才会跳转；运行新检索会取消旧的图谱动画，避免旧证据混入新图。
- 节点和边都有中文语义与置信度；置信度是来源等级（workflow/curated/online/verified/reference/model），不是统计置信区间。
- 工艺步骤和“加工影响”节点会以 `predicts_change` 边连接到配料；边的方向是机理规则，不是实测因果。

### 3D 结构组分

- PDB/PDBQT/GRO 加载后按真实原子自动分组：蛋白、水、离子、糖链、脂质、配体/小分子、其他。
- 默认隐藏水；勾选“显示水”才会绘制。可用预设“仅蛋白+配体”“全部”“隐藏水/离子”快速切换。
- 组分组基于残基名和元素启发式；非标准残基可能落入“其他”，需要人工核对。
- 多构象/MODEL 切换会保留组分选择；导出 PNG 只包含当前可见组分。

### 中英文检索与排序

- 输入中文、英文或混合词均可；系统先做别名扩展，再按词面覆盖、短语命中和术语匹配排序。
- 结果显示 `relevance`（0–1）和 `strength`（高/中/低相关），并列出命中的术语和查询扩展。
- 相关度是检索排序指标，不是文献质量、因果强度或统计显著性。
- 化合物查询和蛋白查询分开路由；不要把蛋白名硬送进化合物库，反之亦然。

### 加工条件与分子变化

- 食品设计结果现在包含“加工条件与分子变化”卡片：温度、时间、pH、aw、热负荷，以及逐条变化预测。
- 每条变化含：受影响组分、变化方向、机制说明、文献来源、置信度、宏观品质影响和验证建议。
- 常见规则：蛋白热变性、美拉德、花青素降解、抗坏血酸损失、脂质氧化、淀粉糊化、糖酸水解、亲水胶体水合、明胶凝胶、乳酸发酵等。
- 规则未触发时显示“低强度/未触发”，并明确这不等于没有变化；所有预测都需要中试、货架期和实测验证。
- “低糖”固体饮料等案例会用高倍甜味剂 + 赤藓糖醇/菊粉替代蔗糖；替代后的甜度、质构和溶解性必须实测。


## 11. 3.2.1 更新：PostgreSQL、资源库与主题

### 知识库

- 服务器启动后运行 `./scripts/start_postgres.sh`，会启动 `bioforge-db`（PostgreSQL 16 + pgvector 0.8.7）并把 JSON/SQLite 语料同步到数据库。
- 设置页“PostgreSQL 知识库”显示连接、版本、文献/文本块/图谱边、向量和体积；资源库页显示相同计数。
- 文献检索优先 PostgreSQL 全文索引；数据库不可用时自动回退 SQLite FTS5，页面会标记 `sqlite-fallback`。
- `literature_chunks.embedding` 是 `vector(1024)`，当前尚未生成嵌入；不要把它描述成已完成的向量检索。

### 资源库与合法全文

- 侧栏“资源库”列出 6 组 38 条来源：化学/食品、蛋白/结构、文献/OA、SCUT/CARSI、标识符工具等。
- 每条含官方链接、许可、接入状态和说明；顶部“来源”按钮可打开快速资源弹层，点击空白或弹层外会关闭。
- DOI/PMID 解析只调用 Crossref、Europe PMC、Unpaywall 等合法接口；找不到 OA 时提示使用学校/出版社授权。
- **不提供 Sci-Hub、付费墙绕过、验证码规避或未授权批量下载。**
- 软件不收集、不记录、不代存校园账号密码；机构登录请使用 SCUT/CARSI 官方页面。管理员可配置 `BIOFORGE_EZPROXY_PREFIX`，软件只拼接官方 EZproxy URL。

### 主题与背景

- 设置 → 外观主题：12 套配色（极光、深海、森林、日落、莓果、石墨、赛博、卡通、国风、实验室、糖果、沙丘），加跟随系统/浅色/深色。
- 主题保存在本机浏览器；背景是低干扰的缓慢光晕动画，`prefers-reduced-motion` 下自动关闭。


## 12. 3.2.2 更新：多组合计算、助手、笔记与双语

### 多受体 × 多配体计算

- 机制计算页新增“受体”和“配体”输入：受体可填 PDB ID（逗号分隔）或本地 PDB 路径；配体可填名称、SMILES 或本地文件。
- 组合数为受体数 × 配体数，最多 12 对；每对在 `pairs/NN_<受体>_<配体>/` 下独立准备和对接。
- 结果按 Vina 最佳亲和力排名，表格显示受体、配体、亲和力与复合物链接；导出 `screening.csv`，报告 `report.html`。
- 根目录 `complex.pdb` 是排名第一的刚性受体 + 第一个 pose 拼装，不是能量最小化结构，也不代表真实结合构象；复合物 MD 只提供短时动力学检查，不是结合自由能。
- “MD 体系”可选“蛋白-配体复合物”（默认）或“仅蛋白”。复合物模式会为最佳对接 pose 生成 GAFF2/AM1-BCC 拓扑，溶剂化、中和后跑 EM + 短 NVT；失败时会回退到蛋白-only，任务卡会显示“复合物回退”，报告记录原因。
- “高级计算范围”可选代表项或全部；复合物 MD 按选定 pair 运行，蛋白-only 模式按唯一受体、CP2K 按唯一配体运行。
- 若某个受体准备失败，排名只包含成功的对，报告会保留失败原因；非标准残基可用 `--delete_bad_res` 自动跳过。

### HADDOCK3 对接

- 机制计算页的“HADDOCK3 对接”卡片支持蛋白-蛋白、蛋白-配体、蛋白-多糖；勾选后创建 HADDOCK3-only 作业，不运行 Vina/MD/QM。
- 蛋白-配体填配体名称或 SMILES；蛋白-多糖填含糖链的 PDB（可写 `1LMQ:B`）。留空链号时自动选择首个合适链。
- 可调采样、容差、select top、flexref/emref、聚类、最小簇、输出模型、聚类截断、核数、种子、超时、vdW/静电/界面权重、介电常数和 mdsteps；参数会写入 `haddock.cfg` 并记录在任务卡。
- 有活性残基时生成 `ambig.tbl`；没有活性残基时使用 cmrest/ranair 回退。活性残基填错会导致模型被拒绝或分数异常。
- HADDOCK score 是任意单位（a.u.，越低越好），不是结合自由能；没有实验参考结构时不把 CAPRI RMSD 当作验证。最佳模型仍需实验验证。
- 任务卡可打开 `best_model.pdb` 的 3D 视图，下载 `capri_ss.tsv`、`capri_clt.tsv`、`haddock_analysis.html`、`stdout.log` 和报告。

### 本地助手与 Obsidian 笔记

- 使用指南页的助手卡片显示 Ollama 状态；问题只发送到本机 `127.0.0.1:11434`，不经过第三方 API。
- 回答是本地模型输出，可能错误；不要输入密码、密钥、未发表数据或个人信息。
- 助手限流 8 次/60 秒；历史保存到 `runtime/assistant/history.jsonl`，按月备份。
- 笔记卡片只读浏览指定 Obsidian 目录；默认 `/media/h3c/Win11Pro X64/data/literature/obsidian/00-BioForge`，可用 `BIOFORGE_OBSIDIAN_DIR` 覆盖。
- 笔记单文件上限 2 MB，禁止目录穿越；软件不写入、不删除、不同步 Obsidian 文件。

### 3D 与图谱

- 3D 着色新增二级结构、残基极性、序列彩虹、B-factor、深度；蛋白/核酸全序列按链分组，配体单独列出。
- 计算作业卡可直接打开复合物 3D，并导出 JSON/CSV；水默认隐藏。
- 含 `md.xtc` 与 `md.tpr` 的 GROMACS 作业会显示“3D 轨迹”按钮；服务器用 `trjconv` 转为缓存 PDB，首次加载较慢，后续走缓存。轨迹只用于检查运动，不是平衡采样或自由能。
- 图谱图例可点击查看节点/边定义；边详情显示来源状态、依据和引用，没有引用的非流程边会显示 caveat。

### 中英切换与主题

- 顶部“中/EN”按钮切换导航、按钮、说明、表单占位符、资源库分组/许可说明、设置页来源目录和动态计算/证据状态；英文页可通过 `?lang=en` 直接打开。
- 病例标题与目标、文献、Obsidian 笔记、在线记录原文和生成结果保留原语言；英文界面不会把中文数据伪装成英文。
- 移动端底部 8 个标签在 320–430 px 宽度内全部显示，不依赖横向滚动；内容区仍支持左右滑动切页。
- 选择会保存在本机；12 套主题各有独立纹理，切换后卡片、导航和 hero 同步染色。


## 3.3.0 证据检索与人工审核

1. 打开“使用指南 → 问 BioForge（证据检索）”。
2. 输入具体问题（蛋白/化合物/食品体系 + 条件）。系统先查本地 10,000 篇 OA 和知识图谱；不足时才查 Europe PMC/OpenAlex。
3. 阅读回答上方的质量分级、路由链和警告：
   - `较强/中等` 仍需核对原文；
   - `偏弱/不足` 不得当作结论；
   - “多数仅有题录/摘要”表示需要找全文。
4. 展开“证据清单”，检查来源、年份、许可和原始链接；外部 OA 记录标为待审核。
5. 展开“图谱概念/关系边”和“逐句核验”；关键词共现不是因果。
6. 人工操作：
   - “审核通过/驳回”写入审核记录；
   - “回滚并重查”保留旧记录并新建 run；
   - “有帮助/无帮助”更新关系权重（不是训练大模型）。
7. 审核队列在回答下方，可点开待审核记录。

注意：RAG 不能替代系统综述、同行评审、法规批准或湿实验；不要输入患者数据、密码、Token 或未公开数据。
